# Themis Benchmark Framework Architecture

## Overview

Themis Benchmark is a deterministic benchmark framework for evaluating Large Language Models (LLMs) on security-related tasks.

The framework executes benchmark prompts, records model responses, evaluates runtime metrics, validates answer quality, and generates benchmark reports.

The benchmark lifecycle is:

```
Definitions
      │
      ▼
Run
      │
      ▼
Runs
      │
      ▼
Evaluate
      │
      ▼
Responses
      │
      ▼
Validate
      │
      ▼
Validation
      │
      ▼
Report
      │
      ▼
Markdown Report
```

# Directory Reference

## definitions/

Contains benchmark definitions.

A definition describes **what** benchmark should be executed.

Typical contents:

```
definitions/

B001.json

B002.json

...

B011.json
```

Each definition contains metadata such as:

- Benchmark ID
- Benchmark Name
- Prompt filename
- Category
- Description

Definitions are immutable descriptions of benchmark scenarios.

---

## prompts/

Contains prompt templates presented to the LLM.

```
prompts/

B001.md

B002.md

...

B011.md
```

One prompt exists for each benchmark definition.

Prompts represent the exact input sent to the model.

---

## expected/

Contains deterministic validation rules.

```
expected/

B001.json

B002.json

...

B011.json
```

Each file defines a validator type plus its rules.

Supported validators:

- `keyword` — required keywords (case-insensitive) and forbidden keywords
- `json` — a ground-truth object under `expected`; each top-level field
  must deep-equal the field in the model's JSON answer

Example:

```json
{
    "benchmark": "B001",
    "validator": "keyword",
    "required": [
        "CVE",
        "CVSS"
    ],
    "forbidden": [
        "guess"
    ]
}
```

Future validator types may include:

- regex
- json-schema
- semantic
- llm-judge

---

## runs/

Raw model execution results.

```
runs/

2026-07-30/

cyberpal20b/

B001.json

B002.json
```

Generated by:

```
themis-bench run
```

Contains:

- prompt
- raw answer
- timestamps
- runtime metadata

These files are never modified after creation.

---

## responses/

Normalized benchmark responses.

```
responses/

2026-07-30/

cyberpal20b/

B001.json

...
```

Generated by:

```
themis-bench evaluate
```

Contains:

- benchmark id
- answer
- token counts
- latency
- TPS
- normalized metrics

Responses are the canonical evaluation artifacts.

---

## validation/

Validation results.

```
validation/

2026-07-30/

cyberpal20b/

B001.json

...
```

Generated by:

```
themis-bench validate
```

Contains:

- benchmark
- score
- passed
- failed
- missing keywords
- forbidden keyword violations

Validation is deterministic.

No AI is used during validation.

---

## reports/

Human-readable benchmark reports.

```
reports/

2026-07-30/

cyberpal20b.md
```

Generated by:

```
themis-bench report
```

Contains:

- benchmark summary
- token statistics
- latency statistics
- TPS
- validation scores
- benchmark comparison table

Reports are intended for human consumption.

---

## docs/

Repository documentation.

Examples:

```
docs/

ARCHITECTURE.md

VALIDATORS.md

BENCHMARKS.md

ROADMAP.md
```

This directory contains design documentation only.

# Internal Packages

The benchmark engine is implemented under:

```
internal/
```

### benchmark/

Responsible for benchmark execution.

Responsibilities:

- load definitions
- load prompts
- execute runtime
- write run artifacts

---

### runtime/

Model runtime abstraction.

Responsibilities:

- Ollama runtime
- future OpenAI runtime
- future Anthropic runtime
- future local inference runtimes

---

### evaluator/

Produces normalized benchmark metrics.

Responsibilities:

- calculate tokens
- generation time
- prompt time
- TPS
- write response artifacts

---

### validator/

Evaluates benchmark correctness.

Responsibilities:

- load expected rules
- validate responses
- compute scores
- write validation artifacts

---

### report/

Generates benchmark reports.

Responsibilities:

- aggregate metrics
- aggregate validation
- produce Markdown reports

# Artifact Lifecycle

```
Definition
      │
      ▼
Prompt
      │
      ▼
Run Artifact
      │
      ▼
Response Artifact
      │
      ▼
Validation Artifact
      │
      ▼
Markdown Report
```

Each stage consumes the previous stage and produces a new immutable artifact.

---

# Design Principles

The framework follows these principles:

- Immutable artifacts
- Deterministic validation
- Reproducible benchmark execution
- Pluggable runtimes
- Pluggable validators
- Human-readable reports
- Simple directory structure
- No hidden state
